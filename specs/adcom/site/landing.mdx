    <h2>What the registry holds</h2>
    <p>AdCOM keeps the code lists that OpenRTB and other specifications cite, such as the device types and the API frameworks. Here each list with codes is one vocabulary, with each code's label from its row, so a specification that cites a list can take its codes from one place.</p>

    <h2>The objects</h2>
    <p>AdCOM also defines <Stat of="objects" /> objects, such as <code>Ad</code> and <code>Device</code>, with <Stat of="keys" /> attribute rows, and the schemas now hold those too (<Decision of="D-049" />): each row is typed by what its Type cell states and by the code list or object it cites, and the rows no rule could read are settled by records that quote them. The records on the objects' known inconsistencies, such as how the protocol buffer definitions type a timestamp or a flag, quote the rows they rest on already.</p>
    <h2>How to read a vocabulary</h2>
    <p>Each list is <code>type: integer</code> and a <code>oneOf</code> of one titled <code>const</code> branch per code, as List: Device Types gives <code><Stat of="walkthrough.target.number" /></code> the title "Connected TV". A list with a <code>500+</code> row is open: one more branch takes a vendor's code of <Stat of="vendorFloor" /> or more. <Clause of="primitives" omits links><Fragment slot="lead">The kernel holds the <Stat of="primitives" count unit="type" /> the schemas need, </Fragment><Fragment slot="some">.</Fragment></Clause></p>
